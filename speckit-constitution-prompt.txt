I am building a Spring Boot web application using Java 21.

Help me create a project constitution that defines the permanent engineering standards for this project. These rules must apply to every feature that will ever be developed.

The constitution should focus only on long-term project principles. Do not include feature-specific requirements, business rules, or implementation details for any individual feature.

Use the following project standards when creating the constitution.

## Technology Stack

* Java 21
* Spring Boot 4
* Maven
* Thymeleaf for server-side rendered views
* Spring Data JPA
* MySQL for production
* H2 for development
* Flyway for database migrations
* Spring Security with form-based authentication

## Architecture

* Follow a layered architecture.
* Organize source code by layer.
* Keep clear separation between Controller, Service, and Repository layers.
* Business logic belongs only in the Service layer.
* Controllers should only handle HTTP requests and responses.
* Repositories should only be responsible for data access.

## Dependency Injection

* Use constructor injection exclusively.
* Never use field injection.

## Data Transfer Objects

* Use Java records for DTOs.
* Do not expose JPA entities directly to the presentation layer.

## Validation

* Validate all user input using Jakarta Bean Validation.
* Validation rules should be enforced consistently across the application.

## Exception Handling

* Use a global `@ControllerAdvice` for application-wide exception handling.
* Display user-friendly error pages instead of exposing internal exceptions.

## Persistence

* Use Spring Data JPA for data access.
* Manage all schema changes with Flyway.
* Prevent N+1 query problems.
* Use lazy loading by default.
* Use pagination for large collections.
* Introduce caching only when there is a measurable benefit.

## Security

* Use Spring Security with form login.
* Follow secure defaults.
* Never expose sensitive information in responses or logs.

## Configuration

* Use `application.properties`.
* Maintain separate `dev` and `prod` Spring profiles.
* Environment-specific configuration should remain outside application code whenever possible.

## Logging

* Use SLF4J for all logging.
* Never use `System.out.println()` or `System.err.println()`.
* Never log passwords, secrets, or other sensitive information.

## Testing

* Write unit tests using JUnit 5.
* Every new business service should include appropriate automated tests.
* Tests should be easy to read, isolated, and maintainable.

## Coding Standards

* Do not use wildcard imports.
* Do not use Lombok.
* Prefer composition over inheritance.
* Reuse existing components before creating new ones.
* Never generate duplicate code.
* Do not introduce additional libraries unless there is a clear and justified need.
* Keep classes and methods focused on a single responsibility.
* Write self-explanatory code. Add comments only when the intent cannot be understood from the code itself.

## General Principles

Create a constitution that encourages consistency, maintainability, readability, testability, security, and long-term scalability.

The constitution should define principles instead of implementation details. Every future feature generated by GitHub Spec Kit should automatically follow these standards.
